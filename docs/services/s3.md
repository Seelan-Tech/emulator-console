## Buckets

**S3** in the sidebar lists your buckets. **Create bucket** checks the name as you type (lowercase letters, digits, dots and hyphens, 3 to 63 characters). Deleting a bucket asks you to **type its name** first.

The emulator caps each bucket at **64 MiB**. See [Troubleshooting](../troubleshooting.md#s3-upload-fails-or-a-bucket-refuses-more-data).

## Browsing objects

Opening a bucket shows its objects as folders and files. The address in the browser always reflects where you are (`…/s3/<bucket>?prefix=images/`), so you can bookmark a folder, share a link, and use the back button.

- **Path** at the top is a breadcrumb; click any part to go up.
- **Filter this folder** narrows the list as you type.
- **New folder** creates a zero-byte `name/` marker, which is how S3 represents an empty folder.
- Tick rows (or **Select all**) to **delete several objects at once**.

## Uploading and downloading

- **Drop files anywhere** on the page, or use the upload button. Several files upload in sequence with progress and a **Cancel upload** button.
- Files up to 8 MB go up in one request. Larger files use **multipart upload** automatically, because the emulator rejects big single uploads; the test suite checks that a file above 8 MB downloads byte for byte identical.
- **Download** streams the object through the console, so a private-CA emulator works without any browser setup.
- **Preview** opens text, JSON, CSV and similar files, and images, in a dialog. Other types can be downloaded.

Uploads are not recorded as fixture steps (a recording would have to embed the file). Creating and deleting buckets is, so a replay recreates the buckets but not the files in them.
